## 2. 外部 OOD 測試資料：`aigrant/taiwan-ly-law-research`

| 項目 | 數字 | 狀態 |
|---|---|---|
| 總筆數 | 2,910 | ✅ |
| 有 `related_laws` 標註 | 1,521 (52.3%) | ✅ 顯式標籤 |
| **與主資料共享 label 的筆數** | **591** | ⚠️ 可用數字 |
| 授權 | **Apache 2.0** | ✅ |
| 格式 | 立法院議題研析報告 | ⚠️ 文風不同 |

### 與主訓練資料的 label 重疊
- **27 / 28** 主資料法規名在 aigrant 中都找得到
- 僅 `票據法` 是主資料獨有
- aigrant 另有 **1,058 個獨有法規名**（住宅法、國民教育法、全民健保法…），不納入共用 label space

### 可用為 OOD 測試的嚴格數量
591 筆 — 即 aigrant 裡 `related_laws` 至少包含 1 個主資料 label space 內法規的筆數。
**意義**：可做 cross-domain generalization 測試（訓練在故事風，驗證在研究報告風）。

### 內容長度警告
- 平均 2,731 字，**51.9% 超過 2,000 字**
- BERT max length 512 tokens ≈ 1,000–1,500 字
- **➜ 對策**：aigrant content 需截斷（取前 1,500 字 或 title + 首段 summary）

## 6. 後續風險提醒（給 implementation plan）

1. **類別不平衡**：77% 刑法 → 議題 ontology 設計要細拆刑法，低頻領域合併
2. **Label noise ~10–15%**：Step 2 自動打標後需抽樣 50 筆人工驗證
3. **aigrant 長文**：BERT 推論前需截斷或摘要
4. **Domain gap**：aigrant 是研究報告、主資料是故事 → 預期 OOD 分數較差，當 limitations 誠實寫
5. **樣本規模**：2,210 筆訓練對 BERT fine-tune **偏少**，需注意 overfitting（early stopping + 小 lr 是必要的）
